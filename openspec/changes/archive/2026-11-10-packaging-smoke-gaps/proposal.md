# Proposal

## Why

The packaged smoke test left two gaps (roadmap, item 1). The `.deb`'s maintainer scripts, generated by jpackage, run `xdg-desktop-menu` under `set -e`: on a machine without the system menus folder `/etc/xdg/menus` (servers, minimal containers) installing it leaves the package half-configured and removing it fails too, so the user can't get rid of it with `apt`. The smoke test hides this by creating the folder before installing. And the Homebrew Cask and the Scoop manifest are rendered and pushed to their repositories after the release is published, with nothing installing them first: a mistake in a template only shows when a user runs `brew install` or `scoop install`.

## What Changes

- The `.deb` built by Gradle installs and uninstalls on a machine without a system menus folder: adding or removing the applications menu entry no longer fails the maintainer script; it prints a warning instead. On a desktop, the menu entry is added and removed as before.
- The Linux smoke test installs the `.deb` on the runner as it comes, without the menus folder (and fails if the runner has one), checks the package is fully configured, removes it, and then installs it again with the menus folder, as on a desktop, checking the menu entry is added.
- The Homebrew Cask and the Scoop manifest are rendered by one script each, used both by the release jobs that push them and by the smoke test.
- The smoke test installs, before anything is published, the Cask rendered for the release on macOS Apple Silicon and Intel, and the Scoop manifest rendered for the release on Windows, from the installers just built: it checks each one points to the installers the release will publish, installs it, runs `shogun --version` from a new shell, and uninstalls it.

## Capabilities

### New Capabilities

- `linux-package-distribution`: the `.deb` the release publishes and how it installs and uninstalls on Debian and Ubuntu machines, with or without a desktop.

### Modified Capabilities

- `packaged-smoke-test`: the Linux scenario runs without the menus folder and covers removal and a desktop install; a new requirement smoke tests the Homebrew Cask and Scoop manifest rendered for the release.

## Impact

- `desktopApp/build.gradle.kts`: the Debian packaging tasks rewrite the `.deb`'s `postinst` and `prerm` after jpackage builds it.
- `.github/smoke/smoke-linux.sh`, new `.github/smoke/smoke-homebrew.sh` and `.github/smoke/smoke-scoop.ps1`.
- New `.github/homebrew/render-cask.sh` and `.github/scoop/render-manifest.sh`; `release.yml`'s `update-homebrew-cask` and `update-scoop-bucket` jobs call them.
- `.github/workflows/smoke-test.yml` takes the version and gets the Homebrew and Scoop jobs; `release.yml` and `release-candidate.yml` pass it.
- Docs: the release process and the packaged smoke test pages (English and Spanish), and the roadmap.
