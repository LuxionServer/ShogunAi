# Spec Delta

## ADDED Requirements

### Requirement: Release assets have build provenance attestations
Every installer and archive a release publishes SHALL have a signed build provenance attestation, generated by the release workflow run that built it and linked to this repository, and the release SHALL be published only after every attestation has been created.

#### Scenario: Verify where a download comes from
- **WHEN** a user downloads `ShogunAi-1.4.0-arm64.dmg` and runs `gh attestation verify ShogunAi-1.4.0-arm64.dmg --repo LuxionServer/ShogunAi`
- **THEN** the verification succeeds and names the release workflow and the commit it was built from

#### Scenario: Modified download
- **WHEN** a file whose contents differ from the published asset is verified the same way
- **THEN** the verification fails

#### Scenario: Attestation fails
- **WHEN** the attestation of any asset can't be created
- **THEN** the release stays a draft and no package manifest is updated

### Requirement: Signing permissions are limited to the attesting job
The release workflow SHALL grant the permissions to mint an identity token and write attestations only to the job that attests the assets, and that job SHALL NOT check out the repository or run the build.

#### Scenario: Build job
- **WHEN** a job that runs Gradle to package an installer runs
- **THEN** it can't request an identity token or write attestations

#### Scenario: Attesting job
- **WHEN** the job that attests the assets runs
- **THEN** it only downloads the built assets, attests them, and holds no `contents: write` permission
