## Why

The release pipeline builds the macOS `.dmg` only on a `macos-latest` runner (Apple Silicon/arm64), and jpackage embeds that runner's arm64 JDK runtime. The resulting installer does not start on Intel (x86_64) Macs. This was identified as a blocker for Intel users while setting up the Homebrew Cask distribution (`homebrew-cask-distribution`): today they have no way to install the app other than building it from source.

## What Changes

- The release build matrix in `.github/workflows/release.yml` gains a second macOS entry that builds the `.dmg` on a GitHub-hosted Intel runner (`macos-26-intel`), alongside the existing arm64 build.
- Each macOS `.dmg` is published as a separate release asset with an architecture suffix in its file name (`ShogunAi-<dmg-version>-arm64.dmg` / `ShogunAi-<dmg-version>-x64.dmg`) so they don't overwrite each other. **BREAKING** for anything that downloads the unsuffixed `.dmg` name.
- The Homebrew Cask is generated by the release workflow from a template versioned in this repository (`.github/homebrew/shogunai.rb`) and selects the `.dmg` and its `sha256` by CPU architecture (`arch arm:/intel:` and `sha256 arm:/intel:`), instead of patching `version`/`sha256` in place in the tap.

## Capabilities

### New Capabilities
- `macos-multi-arch-release-build`: building and publishing separate macOS `.dmg` installers for arm64 and Intel (x86_64) in every release.

### Modified Capabilities
- `homebrew-cask-distribution`: the Cask installs the `.dmg` matching the user's CPU architecture, and the automatic update writes one `sha256` per architecture.

## Impact

- `.github/workflows/release.yml`: one more matrix entry (macOS Intel), an architecture-suffix rename step for `.dmg` files, and an `update-homebrew-cask` job that downloads both `.dmg` files and renders the Cask from the template.
- `.github/homebrew/shogunai.rb` (new): the Cask template.
- The tap (`LuxionServer/homebrew-shogunai`) needs no manual change: the first release that ships this change overwrites `Casks/shogunai.rb` with the generated multi-arch version.
- CI cost: macOS build time/minutes double (two jobs instead of one).
- `README.md`/`README.es.md` and `docs/process/release.md`/`.es.md`: installers per architecture.
- No application code (Compose/Kotlin) changes — packaging and CI only.
